# Next.js Remote Images and S3 Presigned URLs Fix

## What changed

1. **Configured Next.js Remote Image Patterns**:
   - Updated `web/next.config.ts` to add `images.remotePatterns` with wildcards for `**.amazonaws.com` (AWS S3) and `**.googleusercontent.com` (Google OAuth user profile avatars).
2. **Enabled `unoptimized` on S3 Product Images**:
   - In `web/src/features/conversations/components/ConversationDetailsPanel.tsx`, added the `unoptimized` prop to the `Image` component rendering `context.productImageUrl`.

## Why

- **Unconfigured Host Runtime Error**: Next.js 15 blocks remote image sources from domains that are not explicitly whitelisted in `next.config.ts`. When buyers viewed produce details in the conversation panel, S3 URLs from `agrivive-s3-5p3nb0.s3.ap-southeast-1.amazonaws.com` threw a client-side runtime error `next-image-unconfigured-host`.
- **Presigned S3 Query Parameters**: S3 presigned URLs include transient cryptographic signatures (`X-Amz-Signature`, `X-Amz-Date`, `X-Amz-Expires`). Using `unoptimized` ensures the browser downloads the image directly from S3 without Next.js attempting to route them through server-side optimization pipelines that fail on query param invalidation or URL expiration.
