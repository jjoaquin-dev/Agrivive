# Deployment Readiness Criteria

Parent: [[Docs Index]]

**Project/System:** Agrivive (buyer web, seller mobile app, backend API)
**Respondent:** ____________________
**Role:** ☐ Expert  ☐ Seller  ☐ Buyer
**Date:** ____________________
**Build/Version:** ____________________
**Environment:** ____________________

**Purpose:** Decide if Agrivive is ready to go live. Use the system, then rate each criterion.

**Rating scale:** 5 = Excellent (ready) · 4 = Good · 3 = Fair (needs small fixes) · 2 = Poor (needs big fixes) · 1 = Not ready

| No. | Criterion | What to check | Rating (1-5) | Remarks |
| --- | --------- | ------------- | ------------ | ------- |
| 1 | **Features Work** | Every main feature (sign in, listings, reservations, pickup, messages, boost) does what it says. | | |
| 2 | **Correct Results** | Stock, prices, order status, totals and trust points are right and match what the screen shows. | | |
| 3 | **Easy to Use** | A first-time user can finish a task without help. Words are short and clear. | | |
| 4 | **Fast Response** | Pages and actions answer in about 2 seconds or less on normal internet. | | |
| 5 | **Stays Up** | No crashes, frozen screens or lost work. Errors show a clear message and the user can try again. | | |
| 6 | **Account Safety** | Sign-in codes work, a user cannot open another user's data, and wrong roles are blocked. | | |
| 7 | **Data Privacy** | Personal details are kept private. Secrets are not shown in the app or web page. | | |
| 8 | **Works on Devices** | Web works on phone, tablet and computer browsers. The mobile app works on the phones it supports. | | |
| 9 | **Fair and Trusted** | Ranking, trust marks and flags are fair, explained, and can be disputed. | | |
| 10 | **Ready to Launch** | Live setup, backups, notifications, and a plan to fix problems are in place. | | |
| 11 | **Handles Many Users** | Many people using it at once (browsing, reserving, messaging) does not slow it down or break it. | | |
| 12 | **Clear Messages** | Errors, warnings and notices use plain words and tell the user what to do next. | | |
| 13 | **Notices Arrive** | Push, email and in-app updates (new order, reply, boost, trust notice) reach the right person on time. | | |
| 14 | **Fixable and Watchable** | The team can see errors and logs, and can fix and update the system without long downtime. | | |
| 15 | **Rules and Terms** | Terms, privacy and cookie pages are present, and the system follows them (for example, data privacy rules). | | |

## Result

| Total score (max 75) | Average (total ÷ 15) | Verdict |
| -------------------- | -------------------- | ------- |
| | | |

**Verdict guide:** 4.5 to 5.0 = Ready to go live · 3.5 to 4.4 = Ready after small fixes · 2.5 to 3.4 = Not ready, fix first · below 2.5 = Not ready, rework.
**Rule:** Any single criterion rated 1 or 2 must be fixed before launch, whatever the average.
